# 8-bit UI Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restyle the platform portal around an 8-bit pixel-game motif — pixel type, pixel sprites, hard edges, retro animation — without hurting readability or accessibility.

**Architecture:** All visual change lands in the `platform-ui` plugin, which already owns the look. `styles.ts` injects one CSS string (tokens + `.sc-*` classes); `theme.tsx` builds the MUI theme. Backstage's own components stop being styled by hashed class prefix and are styled through the theme's typed `components` overrides instead. A new `sprites.ts` holds pixel art as character grids, rendered to SVG in the app and to canvas for the favicon.

**Tech Stack:** TypeScript, React 18, Backstage 1.53 new frontend system, MUI v4/v5 bridge via `@backstage/theme`, Jest + Testing Library, Playwright for visual checks.

## Global Constraints

- Branch: `feat/8bit-ui`. Do not merge to `main` without explicit approval.
- Design source of truth: `specs/2026-08-03-8bit-ui-design.md`.
- Pixel type is for chrome only: headings, nav, buttons, badges, counters. Body copy, table cells, JSON and log output stay Inter/monospace.
- The colour picker keeps its six swatches, its `localStorage` key `platform-scheme`, and the `--sc-primary` contract.
- Every animation lives inside `@media (prefers-reduced-motion: no-preference)` and uses `steps()`, never `ease`.
- Sprites are `aria-hidden="true"`; state is always conveyed by text as well.
- No game mechanics: no XP, points, achievements, leaderboards, sound, or game-flavoured copy.
- Run tests from `backstage/`: `CI=true yarn test [path-filter]`. The per-package `yarn workspace … test` script does **not** work (no `@backstage/cli` dependency in `platform-ui`).
- Every task ends green: `yarn tsc`, `CI=true yarn test`, `yarn lint:all`.

```ts
import { RequestState } from '@internal/plugin-platform-common';

/** Sprites are authored on a 16x16 grid: '#' is a filled pixel, '.' is empty. */
export const SPRITE_SIZE = 16;

export type Sprite = readonly string[];

/**
 * One rect per horizontal run of filled pixels. Runs are merged because a 16x16
 * glyph is ~40 rects instead of ~120 individual pixels, and both renderers (SVG
 * and canvas) draw rects.
 */
export function spriteRects(
  sprite: Sprite,
): Array<{ x: number; y: number; w: number }> {
  const rects: Array<{ x: number; y: number; w: number }> = [];
  sprite.forEach((row, y) => {
    let x = 0;
    while (x < row.length) {
      if (row[x] !== '#') {
        x++;
        continue;
      }
      const start = x;
      while (x < row.length && row[x] === '#') x++;
      rects.push({ x: start, y, w: x - start });
    }
  });
  return rects;
}
```

```tsx
/**
 * Renders a pixel grid as SVG rects. `shape-rendering: crispEdges` is what keeps
 * the edges hard at every size — without it the browser antialiases the pixels
 * back into a smooth shape.
 */
export function PixelSprite({
  sprite,
  className,
}: {
  sprite: Sprite;
  className?: string;
}) {
  return (
    <svg
      className={className}
      viewBox={`0 0 ${SPRITE_SIZE} ${SPRITE_SIZE}`}
      fill="currentColor"
      shapeRendering="crispEdges"
      aria-hidden="true"
      focusable="false"
    >
      {spriteRects(sprite).map(r => (
        <rect key={`${r.x}-${r.y}`} x={r.x} y={r.y} width={r.w} height={1} />
      ))}
    </svg>
  );
}
```

```ts
import { SCHEMES } from './SchemeRoot';

/** WCAG relative luminance for an "H S% L%" triplet. */
function luminance(hsl: string): number {
  const [h, s, l] = hsl.split(' ').map(v => parseFloat(v));
  const sN = s / 100;
  const lN = l / 100;
  const k = (n: number) => (n + h / 30) % 12;
  const a = sN * Math.min(lN, 1 - lN);
  const f = (n: number) =>
    lN - a * Math.max(-1, Math.min(k(n) - 3, Math.min(9 - k(n), 1)));
  const lin = (x: number) => (x <= 0.03928 ? x / 12.92 : ((x + 0.055) / 1.055) ** 2.4);
  return 0.2126 * lin(f(0)) + 0.7152 * lin(f(8)) + 0.0722 * lin(f(4));
}

const contrast = (a: string, b: string) => {
  const [hi, lo] = [luminance(a), luminance(b)].sort((x, y) => y - x);
  return (hi + 0.05) / (lo + 0.05);
};

describe('colour schemes', () => {
  it('every scheme clears 4.5:1 between its accent and its foreground', () => {
    for (const s of SCHEMES) {
      const ratio = contrast(s.hsl, s.fg);
      expect(`${s.id}:${ratio >= 4.5}`).toBe(`${s.id}:true`);
    }
  });

  it('keeps six schemes with stable ids', () => {
    expect(SCHEMES.map(s => s.id)).toEqual([
      'violet', 'blue', 'green', 'rose', 'amber', 'slate',
    ]);
  });
});
```

## Notes for the implementer

**The sprite art is a starting point, not a specification.** The grids in Task 2 are drawn to be legible at 16px, but they are the part most worth iterating on once you see them at 6× on a real page. Changing them is a data edit — the tests assert grid squareness and state coverage, not specific pixels.

**Where the risk actually is.** Task 1 (the override migration) is the one that can silently break unrelated pages, which is why it ships first and alone with a before/after comparison. Task 7 (the nav) is where the font's extra width will bite, at the 68px collapsed rail.

**What is deliberately not here.** TechDocs content pages keep their reading typeface. No backend, request model or API change appears in any task — this is a restyle.
